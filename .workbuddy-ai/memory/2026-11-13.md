## flutter_patcher 与本机 Flutter SDK 兼容性结论

- 本机 SDK：`/Users/zcj/D/work_zbcx/Android/env/flutter` → Flutter 3.41.6 stable / Dart 3.11.4（framework rev db50e20）。

## 本机是 Intel Mac：flutter_patcher 无法本地 build/patch（已确认）

- `uname -m` = x86_64，CPU i7-8850H → `HostIdentity.current()` 判定 `macos-x64`。
- `requireSupportedHost()`（`lib/src/cli/sdk/host.dart:105`）是**所有**命令的唯一门禁，`build/patch/serve/init/keys/publish` 全走它；
  `verifiedTargets` 与 `implemented` 都只有 `linux-x64 / windows-x64 / macos-arm64`，`macos-x64` 连 implemented 都不在，
  因此 `FLUTTER_PATCHER_UNVERIFIED_HOST=1` 这个后门**无效**（它要求 implemented.contains）。
- 实测：`dart run flutter_patcher build android` →
  `{"code":"HOST_UNSUPPORTED","message":"Supported build hosts: linux-x64, windows-x64, macos-arm64; detected macos-x64."}`
- 根因不是 SDK 版本：引擎资产 `flutter_patcher_artifacts` 的 `engine-<ver>-<hash>/engine.manifest.json` 里
  `gen_snapshot` 只有 linux-x64 / windows-x64 / darwin-arm64 三份，**没有 darwin-x64**。
  要本地支持 macos-x64 必须自己为 darwin-x64 编译打过补丁的 gen_snapshot（engine + depot_tools，重活）。
- 正确的 Flutter SDK 路径：`/Users/zcj/D/work_zbcx/Android/env/flutternew`（3.47.9 / Dart 3.13.7），

## 更新地址策略：局域网明文 HTTP（走 app 侧自定义下载）

- 客户端 `lib/src/io.dart` 的 `updateUri()` 只允许 https，或 http 指向 `127.0.0.1/::1/localhost`；
  局域网 IP 必然抛 `FormatException: Patch downloads require HTTPS without URL credentials`。
  这是防中间人注入可执行代码的策略，不是 bug。
- 地址必须填**目录**：`checkUpdate` 内部 `GET <url>/<fileName>`（`lib/flutter_patcher.dart:311`），
  填成 `.../dist/1-arm64-v8a.fptc` 会拼成 `.../fptc/fptc`，Tomcat 日志里能看到 404。
- **用户明确要求不改库**（真实项目直接依赖 flutter_patcher）。曾经加过
  `FLUTTER_PATCHER_INSECURE_HTTP` dart-define 放行私有网段，**已撤销**：现在 `io.dart` 只多了一段
  指向 example 的文档注释，逻辑与上游逐字节一致。
- 正解：example 走自定义下载（`patchTarget` → 自己取前 146 字节 → `inspectPatch` 判新鲜度 →
  自己整包下载 → `applyPatchBytes`）。地址/协议由项目自己决定，指纹/SHA-256/签名校验仍由库完成。
  真实项目里同样只需这三步，不必碰库。
- 实测通过：`GET http://192.168.100.198:8080/dist/3-arm64-v8a.fptc` → 安装完成 → 冷启动显示
  「正在运行补丁 1794549134」。（注意本机 IP 会随网络变：曾在 192.168.239.82，后为 192.168.100.198。）
- USB 方案仍然更省事：`adb reverse tcp:8080 tcp:8080` + `http://127.0.0.1:8080/dist`，无需重建宿主。

## CI 上的两个必踩坑

- **依赖漂移**：`archive` 经 flutter_patcher 进宿主，补丁改不了它。CI 在 pub.dev 解析到 4.7.0（宿主 4.6.0）
  → `PATCH_PINNED_PACKAGE_CHANGED`。**提交 pubspec.lock 无效**：本机 lock 走 `pub.flutter-io.cn` 镜像，
  与 CI 的 pub.dev 源不一致时 pub 直接忽略 lock 重新解析。正解：`example/pubspec.yaml` 里
  `dependency_overrides: archive: 4.6.0`（插件报错信息本身就这么建议）。
- **签名不稳定**：GitHub runner 每次生成新的 debug keystore，宿主重建后 `adb install -r` 报
  `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，必须 `adb uninstall` 再装（会清掉已装补丁状态）。
  **已解决**：宿主改用用户正式 keystore（见下节），签名稳定，`install -r` 可直接覆盖升级。
- 换宿主必须同时改 `example/pubspec.yaml` 的 versionCode（`1.0.0+1` → `1.0.1+2`），
  否则新旧 baseline 按同一个 versionCode 混淆，补丁文件名也不会变。

## 重要坑：补丁启动后 5 秒内的未捕获异常会触发熔断回滚

- 现象：补丁装上、冷启动显示 PATCHED，2.5 秒后日志出现
  `[FlutterPatcher] SocketException`，紧接着 `Diag: record status=DROPPED_CIRCUIT_BREAKER`，
  状态卡变成「崩溃后已自动回滚补丁」，已安装补丁变「无」。
- 原因：`PatchBootstrap.run` 在首帧后 `verifyAfter`（默认 5s）内挂了
  `PlatformDispatcher.onError` / `FlutterError.onError`，任何逃逸异常都算启动失败；
  `init(maxCrashCount: 1)` 是 fail-fast。当时是 example 的 `_fetch` 抛 `SocketException` 没被捕获。
- 修复：`_fetch` 把网络异常转成 `PatcherException`，`_run` 用 `catch (e)` 兜住一切。
  已作为补丁验证通过（run 43384936135，`status=PATCHED`，文案「基线已持久化」）。
- 熔断状态存在 app 数据里，`pm clear` 在这台华为机上被拒，只能 `adb uninstall` + 重装宿主。
